# Reliable Data Transfer over UDP

This project implements reliable file transfer mechanisms on top of UDP using three ARQ protocols:

- Stop-and-Wait ARQ
- Go-Back-N ARQ
- Selective Repeat ARQ

The main objective is to demonstrate how reliability can be added to UDP using acknowledgements, sequence numbers, timeouts, retransmissions, checksums, and sliding-window techniques.

## Features

The project includes:

- UDP socket programming in C
- Reliable file transfer
- Sequence numbers
- ACK handling
- Timeout-based retransmission
- Packet loss simulation
- ACK loss simulation
- Packet corruption simulation
- Checksum-based corruption detection
- Duplicate packet handling
- Go-Back-N sliding window
- Selective Repeat buffering
- Selective retransmission
- File integrity verification
- Performance comparison of all three protocols

## Protocols Implemented

### 1. Stop-and-Wait ARQ

The sender transmits one packet and waits for its acknowledgement before sending the next packet.

If the ACK is not received before the timeout, the same packet is retransmitted.

Alternating sequence numbers are used to identify new and duplicate packets.

### 2. Go-Back-N ARQ

Go-Back-N uses a sliding window so that multiple packets can be transmitted before waiting for acknowledgements.

The receiver accepts only the next expected packet.

If a packet is lost, later out-of-order packets are discarded.

After a timeout, the sender retransmits all unacknowledged packets starting from the base of the window.

### 3. Selective Repeat ARQ

Selective Repeat also uses a sliding window, but the receiver can buffer out-of-order packets.

Each packet is acknowledged individually.

Only packets whose ACKs are missing are retransmitted.

This reduces unnecessary retransmissions compared with Go-Back-N.

## Channel Emulator

The project contains a simple channel emulator used to simulate unreliable network behavior.

It can simulate:

- packet loss
- ACK loss
- packet corruption

This allows the reliability mechanisms of each protocol to be tested.

## Checksum

A simple additive checksum is calculated for the packet data.

The receiver calculates the checksum again after receiving a packet.

If the calculated value does not match the checksum stored in the packet, the packet is considered corrupted and is discarded.

Run the commands from the root of the project.

./receiver

./sender

## Performance Testing

The three protocols were tested under the following packet-loss rates:

- 0%
- 5%
- 10%
- 20%

For each condition, three runs were performed and the average values were calculated.

The following metrics were measured:

- total send attempts
- retransmissions
- transfer time
- goodput

ACK loss and corruption were disabled during the performance comparison so that the effect of packet loss could be studied independently.

## Main Observations

As packet loss increases, all three protocols experience increased transfer time and reduced goodput.

Stop-and-Wait is simple and reliable, but it waits for an acknowledgement after every packet.

Go-Back-N can transmit multiple packets using a sliding window, but packet loss can cause several unacknowledged packets to be retransmitted.

Selective Repeat performs better under higher packet-loss conditions because it buffers out-of-order packets and retransmits only the specific packets whose acknowledgements are missing.

The experimental results therefore show that Selective Repeat uses network transmissions more efficiently under unreliable conditions.
